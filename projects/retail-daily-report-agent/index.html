유통 일일 실적 보고 자동화 에이전트

매일 아침 쿼리 결과를 넣으면 보고서와 집계표가 나오고, 발송·발주는 사람 결재 뒤에만 확정되는 유통업 운영 에이전트 진단과 PoC

8항목보고서 생성 전 자동 입고검사 검출
60개산출물 인수 검증 계층 합계 등식
99항목약속 원장 QA(충족 74 · 조건부 16)
17개시연 작업(기본·표준·확장·프리미엄)

문제

국내 의약품·소모품 유통사는 매일 아침 쿼리를 돌려 받은 CSV를 사람이 엑셀 보고서에 옮겨 부서별 일계표와 실적 보고를 만들었습니다. 최종 보고서에서는 같은 기준값을 쓰는 수식 88곳이 표를 참조하지 않고 값을 다시 입력하고 있었고, 그중 20곳이 표와 어긋나 있었습니다.

ERP 파일이 늦게 오거나 발신처가 표 양식을 바꾸는 날이면 마감 시각 전에 수동으로 처리할 수밖에 없었고, 조회·전망·우선순위 판단까지 에이전트가 돕는 방안도 함께 검토해야 했습니다.

접근

  • 현장 방문 진단으로 병목을 세 가지로 좁히고, 요구를 «CSV 3종을 넣으면 보고서가 나온다»는 최소 견본으로 먼저 확인했습니다.
  • 보고서를 만들기 전에 데이터를 검사하는 단계를 두고, 검사 규칙은 새로 만든 것이 아니라 데이터에 이미 성립하는 등식을 받아쓰는 방식으로 정했습니다.
  • 숫자는 검증된 계산 스크립트가 내고, 언어 모델은 질문 이해와 근거 정리, 판단 제안만 맡도록 역할을 분리했습니다.
  • 발송은 승인 1단계 / 이상 시 보류 / 완전 무인 세 모드로 나누고 기본값을 «생성·검증까지 끝내고 발송 직전에 사람이 한 번»으로 두었습니다.
  • 시연 단계에서는 약속한 범위를 99항목 원장으로 만들고, 원본 DB에서 독립적으로 다시 계산해 화면 값과 대조하는 방식으로 판정했습니다.

구조

수집SQL 결과·ERP 파일·메일 첨부 3구간에서 입력을 모으고, 마감 시각에서 역산한 재시도 정책을 적용합니다.
입고검사교차 등식으로 데이터를 먼저 검사해 차단·확인·자동보정·정보로 분류합니다.
생성부서별 일계표·담당자별 실적·지역 분석 보고서와 엑셀 집계표를 만듭니다.
인수 검증계층 합계 등식으로 산출물을 검증하고, 기존 오류와 새로 생긴 오류를 구분합니다.
사람 결재발송과 발주·배분은 결재 게이트에서 승인된 뒤에만 확정되고 서명 기록이 남습니다.
조회·운영운영 콘솔과 대화형 조회로 실행 기록·승인 대기·달성률을 확인합니다.

주요 기능

데이터 입고검사보고서 생성 전에 세 파일을 교차 검사해 원본에 공란이던 칸을 계산으로 채우고 이상치를 미리 알립니다.
장애 시나리오 재현ERP 파일 미도착, 발신처 양식 변경 같은 날을 명령 옵션으로 재현해 대응 흐름을 보여 줍니다.
사람 결재 게이트발주·배분·발송은 사람의 승인 뒤에만 실행되고, 반려 경로도 기록합니다.
결정론 계산 CLI와 스킬전망 범위(낙관·기준·비관)는 규칙이 계산하고, 에이전트는 계산 결과와 근거를 읽고 판단을 제안합니다.
재생 모드리허설을 녹화해 두어 인터넷이 끊긴 현장에서도 모델 호출 없이 같은 장면을 보여 줄 수 있습니다.
합성 더미 데이터 생성기고객 데이터 없이 업무 흐름을 심은 합성 데이터로 시연을 먼저 만들고 흐름별로 DB와 대조합니다.

결과

  • 진단 문서 22쪽, PoC 견본 36개 파일, 데모 영상(3분 55초)을 전달해 진단·견본 범위의 역무를 마쳤습니다.
  • 견본은 CSV 3종을 넣으면 보고서 4장과 엑셀 1개를 1초 미만에 만들고, 실제 데이터에서 입고검사 8항목(차단 2 · 확인 3 · 자동보정 2 · 정보 1)을 검출했습니다.
  • 이어서 4단계 시연 PoC를 만들었고, 최종 리허설은 109턴 31.1분 동안 턴 실패 0, 수치 대조 27개 FAIL 0이었습니다.
  • 시연 스택·결재 게이트·검증 하네스는 다른 업무에도 쓸 수 있는 재사용 자산으로 정리했습니다.

포인트

약속을 원장으로 만들고 원본 DB에서 독립적으로 다시 계산하는 QA가 실제 결함을 잡았습니다. 재생 시 발주 번호가 «순서가 맞아서 우연히 맞던» 상태나, 검증기 자신의 오판도 이 방식으로 드러났습니다.
